Tracks

geneinfo.widget.Tracks(chroms=None, *, assembly=None, **kw)

WebGL2 genomic segment viewer rendered as a Jupyter widget.

Build a stack of tracks by chaining the add_*_track methods, then display the instance directly in a notebook cell. All pan / zoom is uniform-only (zero CPU/GPU buffer work per frame); segment viewport culling uses sorted attribute-pointer offsets.

Parameters

chroms : dict of str to int, or str = None

Chromosome sizes as a {chrom: length} mapping, or an assembly name such as 'hg38'. The first chromosome is shown initially.

assembly : str = None

Assembly name ('hg38', 'rheMac10', …) whose chromosome sizes are looked up with :func:geneinfo.coords.chromosome_lengths; an alternative to chroms. Give one of chroms and assembly, not both. The assembly is also the default for :meth:add_gene_track.

****kw** : = {}

Passed on to :class:anywidget.AnyWidget; theme= overrides the default theme (see :func:set_default_theme).

Track types

:meth:add_segment_track Instanced GPU rectangles with automatic level-of-detail (LOD) density fallback when zoomed out. :meth:add_heatmap_track R8 texture rendering; handles 10 k+ individuals at 60 fps. :meth:add_gene_track Exon blocks plus intron connectors (drawn on the 2D overlay). :meth:add_point_track Point cloud (gl.POINTS). :meth:add_line_track Connected polyline per group (gl.LINE_STRIP). :meth:add_fill_track Fill-between two curves with optional pos/neg colour split. :meth:add_histogram_track Vertical bars with multi-resolution LOD. :meth:add_arc_track Arcs linking pairs of genomic positions. :meth:add_ucsc_track A UCSC Genome Browser track fetched by name and drawn as a point, line, histogram, fill, segment or heatmap track.

Point and line tracks accept y_scale='log' for a base-10 log y-axis.

Toolbar

The widget renders a single-row toolbar above the canvas:

Chromosome dropdown Switches the visible chromosome and resets the viewport to the full chromosome span. Position box Free-text region selector. Accepts chr1:1,000–2,000 or chr1:1000-2000 (the chromosome prefix is optional and defaults to the current one). Press Enter to jump. ＋ Zoom in Halves the visible window around its centre. － Zoom out Doubles the visible window around its centre (clamped to the chromosome). ⌂ Reset view Restores the viewport to the full chromosome (or, when a heatmap defines a tighter pan range, that range). ⟲ Recompute heatmap(s) Visible only when at least one heatmap track is present. Re-bins every heatmap at the current viewport for higher resolution. Routed through the _cmd_heatmap_recompute command to :meth:_rebin_heatmap_for_view. ◱ Restore global heatmap Visible only when at least one heatmap track is present. Restores the original whole-chromosome heatmap pixels via :meth:_restore_heatmap_global. ⧉ Snapshot Composites the WebGL and overlay canvases and writes a PNG to the system clipboard (falls back to a file download when clipboard access is denied). The button briefly flashes ✓ on success or ! on failure. LOD badge Read-only indicator showing the current segment-track render mode: ▬ segments when individual rectangles are drawn, ▒ density when the density LOD is active.

Pan and zoom

Mouse wheel Scroll wheel zooms in/out anchored on the cursor’s genomic position. The zoom-step factor per wheel tick is :attr:zoom_speed. Click-drag Press and drag inside the plot area to pan along the chromosome. Double-click Halves the visible window around the click position (a faster alternative to the ＋ button when targeting a specific location). Keyboard (when the widget has focus or hover) ← / → pan by 15 % of the current window. + / = zoom in by 1.5×; - zooms out by 1.5×. Tooltip Hovering over a track displays a tooltip whose contents come from the track’s tip_fmt / tip_label. The tooltip disappears on mouseleave.

Synchronised attributes

These traits round-trip between Python and the browser; assigning them from Python updates the rendered view immediately.

chrom_sizes : dict of str to int Chromosome name → length in base pairs. Set once via :meth:__init__; re-assigning it rebuilds the dropdown and the pan-clamp ranges. track_configs : list of dict One config per track. Maintained by the add_*_track methods and :meth:remove_track / :meth:clear_tracks; do not mutate directly. track_data : dict Track-id-keyed payloads consumed by the JS uploader. Maintained by the add_*_track methods and :meth:remove_track / :meth:clear_tracks; do not mutate directly. viewport : dict {'chrom': str, 'start': int, 'end': int}. Use :meth:set_viewport or :meth:zoom_to to change it from Python; the JS side updates it in response to pan/zoom and toolbar input. zoom_speed : float, default 1.02 Multiplicative zoom step per wheel-tick. Higher values zoom faster. pan_speed : float, default 1.0 Multiplier for click-drag pan velocity (genomic units per CSS pixel of mouse movement). min_span : int, default 500 Narrowest viewport width in base pairs — the point past which zooming in stops. Applies to the wheel, double-click and the + key alike. Lower it to inspect individual bases (e.g. min_span=100); it is clamped to the chromosome’s own span, so a value larger than the chromosome cannot lock the view. theme : dict Colour palette and layout knobs. See :data:DARK_THEME and :data:LIGHT_THEME for the recognised keys; numeric values like sidebar_w (CSS pixel width of the left label column) live alongside the colour strings. Mutating the trait via viewer.theme = {...} re-applies the theme without reload.

Examples

>>> viewer = Tracks(chrom_sizes={'chr1': 248_956_422})
>>> (viewer
...  .add_gene_track(assembly='hg38')
...  .zoom_to('chr1', 50_000_000, window=10_000_000))
>>> viewer  # display in a notebook cell

add_arc_track

geneinfo.widget.Tracks.add_arc_track(
    df,
    name,
    *,
    pos1='pos1',
    pos2='pos2',
    group_by=None,
    color_map=None,
    palette=None,
    height=None,
    arc_height=None,
    alpha=0.9,
    line_width=1.5,
    tip_fmt=None,
    tip_label=None,
)

Add an arc track connecting pairs of positions on the same chromosome.

Each record is drawn as a quadratic-Bezier curve from pos1 to pos2 with a fixed apex height above the track baseline, clamped so the apex never leaves the track band. Useful for splice junctions, Hi-C interactions, structural-variant links, and similar pairwise-coordinate data.

Parameters

df : pandas.DataFrame

Long-format frame with columns chrom, pos1, pos2 (names configurable via pos1 / pos2) and the optional group_by column.

name : str

Track display label shown in the left panel.

pos1 : str = 'pos1'

Column names for the two endpoints. Order within a row doesn’t matter — the track normalises to (min, max).

pos2 : str = 'pos1'

Column names for the two endpoints. Order within a row doesn’t matter — the track normalises to (min, max).

group_by : str = None

Column whose unique values become separately-coloured arc groups. When omitted, all arcs share a single colour.

color_map : dict = None

{group_value: '#rrggbb'}. Omitted means the palette cycle supplies one colour per group.

palette : str, list, or matplotlib.colors.Colormap = None

Qualitative palette; used only when color_map isn’t given.

height : int = None

Total track height in CSS pixels. When omitted it is derived from arc_height (arc_height + 6) so the band fits the arcs; if both are omitted the track defaults to 60.

arc_height : int = None

Apex height above the baseline in CSS pixels — how tall the arcs are drawn. When omitted it fills the usable band (height - 6, where 6 = 2 * PAD_V). If both height and arc_height are given and the apex would overflow the band, arc_height is clamped to height - 6 (with a warning) so the arcs never leave the track.

alpha : float = 0.9

Line opacity (0..1).

line_width : float = 1.5

Stroke width in CSS pixels.

tip_fmt : str = None

Python format string for tooltips. Available keys: {group}, {pos1}, {pos2}, {span}.

tip_label : str = None

Heading shown above the tooltip body. Defaults to f'{name}:'.

Returns

: Tracks

self, to support fluent chaining.

add_fill_track

geneinfo.widget.Tracks.add_fill_track(
    df,
    name,
    *,
    x='pos',
    y=None,
    y_lo=None,
    y_hi=None,
    group_by=None,
    color_map=None,
    palette=None,
    color_pos='C0',
    color_neg='C3',
    alpha=1.0,
    height=60,
    y_range=None,
    baseline=None,
    step=None,
    zoom_windows=(256, 1024, 4096),
    aggregate='envelope',
    y_range_per_zoom=True,
    tip_fmt=None,
    tip_label=None,
    density_windows=None,
    y_range_per_lod=None,
)

Add a fill-between track.

Either supply y (fill from a single curve to baseline) or both y_lo and y_hi (fill between two curves). When baseline is set, the area above and below it can be drawn in distinct colours.

A missing value (NaN in y, or in either y_lo or y_hi) breaks the fill, as in matplotlib: nothing is filled between the samples on either side of it. Positions that simply have no row are bridged, so add NaN rows where the fill should break. When zoomed out, a bin whose samples are all NaN is a gap; other bins aggregate their non-NaN samples.

Parameters

df : pandas.DataFrame

Long-format frame with columns chrom, the column named by x, plus the relevant y column(s).

name : str

Track display label shown in the left panel.

x : str = \'pos\'

Column for genomic position.

y : str = None

Column for a single curve; the fill runs between it and baseline (0 unless you move it). An alias for y_hi, accepted whenever y_lo is not passed — pass one spelling or the other, never both.

y_lo : str = None

Column for the lower y boundary. Given without y_hi it is the single curve instead, and the upper edge of the fill is baseline (0 by default).

y_hi : str = None

Column for the upper y boundary. Given without y_lo it is the single curve instead, and the lower edge of the fill is baseline (0 by default) — the same thing y does. With neither boundary nor y supplied, the columns 'lo' and 'hi' are used.

group_by : str = None

Column whose unique values become separate groups, each drawn in a single colour from color_map / palette. Works with a single curve (y) and with a two-curve band. Because the colour identifies the group, there is no positive / negative split: color_pos and color_neg are ignored, and the fill on both sides of baseline takes the group’s colour.

color_map : dict = None

{group_value: '#rrggbb'}. When omitted, group colours cycle through 'C0'..'C9'.

palette : None, str, list, or matplotlib.colors.Colormap = None

Group palette, used when color_map is omitted. None uses the active matplotlib axes.prop_cycle. Strings are resolved as colormap names first ('viridis', 'tab10', …) then fall back to single-colour literals.

color_pos : str = \'C0\'

Colour for the region above baseline. Resolved with :func:resolve_color. Ignored when group_by is given.

color_neg : str = \'C3\'

Colour for the region below baseline. Ignored when group_by is given.

alpha : float = 1.0

Fill opacity in [0, 1], applied to every group. Values outside the range are clamped. Lower it to see overlapping groups through each other.

height : int = 60

Track height in CSS pixels.

y_range : tuple of (float, float) = None

(y_min, y_max). Auto-computed from data with 5% padding when omitted.

baseline : float = None

The fill’s other edge in single-curve mode, and the y value at which the positive / negative colour split occurs. Defaults to 0 whenever a single curve is given (as y, y_hi, or y_lo). With both y_lo and y_hi it defaults to None, which disables dual colouring. Pass an explicit number in lo/hi mode to re-enable the split. With group_by the split is always off and each group is drawn in its own colour.

step : str = None

Step mode for a staircase fill, matching matplotlib’s fill_between(step=...). One of 'pre', 'post', 'mid'. None gives smooth linear interpolation.

zoom_windows : int, str, tuple thereof, or False = (256, 1024, 4096)

Level-of-detail resolutions. Each entry is either a bin count (int) or a physical bin size (str such as '10kb'); a bp size is resolved to a count per chromosome. The renderer draws the coarsest level whose bins still cover at least 2 CSS pixels and falls back to the raw samples once they are far enough apart, so a dense band stays responsive when zoomed out. Pass False (or ()) to disable LOD and always ship only the raw samples.

aggregate : ('envelope', 'mean') = 'envelope'

How samples sharing a bin are combined. 'envelope' takes the min of the lower and the max of the upper boundary, so a coarse level never draws a narrower band than the data it summarises. 'mean' averages each boundary, which smooths the band but can hide spikes. In single-y mode the aggregate is applied to y before the split against baseline.

y_range_per_zoom : bool = True

Emit a per-level (y_min, y_max) so the axis rescales when the renderer switches levels. Ignored when y_range is given explicitly.

tip_fmt : str = None

Python format string for tooltips. Available keys: {group}, {lo}, {hi}, {x}. Tooltips always report the raw samples, never the aggregated levels.

tip_label : str = None

Heading shown above the tooltip body. Defaults to f'{name}:'.

density_windows : tuple | int | str | None = None

Deprecated aliases of zoom_windows and y_range_per_zoom. Passing one emits a DeprecationWarning.

y_range_per_lod : tuple | int | str | None = None

Deprecated aliases of zoom_windows and y_range_per_zoom. Passing one emits a DeprecationWarning.

Returns

: Tracks

self, to support fluent chaining.

Raises

: TypeError

If both y and y_hi are supplied — they are two spellings of the same curve.

: ValueError

If y is combined with y_lo, if step is not in {None, 'pre', 'post', 'mid'}, or if aggregate is not in {'envelope', 'mean'}.

add_gene_track

geneinfo.widget.Tracks.add_gene_track(
    genes_data=None,
    exons_df=None,
    *,
    assembly=None,
    name='Genes',
    color=None,
    height=None,
    collapse=True,
    label_padding=0,
    highlight=None,
    highlight_color=None,
    highlight_fill_color=None,
    highlight_spine_color=None,
    highlight_outline_color=None,
    highlight_label_color=None,
    highlight_halo_color=None,
    tip_fmt=None,
    tip_label=None,
)

Add a gene / exon annotation track.

Parameters

genes_data : dict or pandas.DataFrame = None

Either a dict mapping chromosome to a list of (gene_name, chrom, start, end, strand, transcripts) tuples (as returned by geneinfo), or a DataFrame with columns chrom, start, end, name, strand. Mutually exclusive with assembly; exactly one must be provided.

exons_df : pandas.DataFrame = None

Frame with chrom, gene_name, start, end. Only used with the DataFrame form of genes_data.

assembly : str = None

Assembly identifier (e.g. 'hg38'). When given, genes_data is fetched automatically via :func:geneinfo.coords.gene_coords_region for every chromosome in :func:geneinfo.coords.chromosome_lengths. Mutually exclusive with genes_data. If the assembly was already supplied to :class:Tracks itself, it is inherited from there and passing it again here raises :class:ValueError.

name : str = \'Genes\'

Track display label.

color : str = None

Exon block colour for non-highlighted genes (matplotlib colour spec). Falls back to theme['gene_exon'].

height : int = None

Track height in CSS pixels. Defaults to the required number of rows (positive strand above, negative below, each with sub-lanes on overlap).

collapse : bool = True

If True, merge exons across all transcripts into a single union set. If False, each transcript becomes its own row.

label_padding : float = 0

Extra room reserved around every gene for its label, in kilobases — 200 means 200 kb (200,000 bp), and fractions are allowed (0.5 is 500 bp) — when assigning rows. The room is split evenly on both sides, matching the label the renderer draws centred on the gene, so two neighbours are pushed onto separate rows exactly when the gap between them is smaller than label_padding, whatever their strands. Modeled as an invisible margin around each gene: row packing, label centring and label collision all see the padded extent, while the spine, exons, arrows and tooltip range continue to reflect the gene’s true bounds. 0 reproduces plain overlap-only packing. Raising this does pull the zoom at which labels appear wider, since labels never collide across rows — but it buys that only by adding rows, and the exchange rate is poor: roughly 2-4x the rows per doubling of the labelled span. Rows need about 30 px each (an 11 px label band plus the exon and a gap), so a height of 300 affords only ~10 before label bands start overlapping their neighbours. Reaching chromosome-wide labels this way would take dozens to hundreds of rows, so treat it as a modest adjustment rather than a way to label a whole chromosome. It is also a fixed genomic distance chosen here, so it does not adapt as you zoom, and raising height alone does not help — height only adds vertical air between the rows packing already decided on.

highlight : list of str or dict of str to list of str = None

Either a list of gene names (treated as {'fill': [...]}) or a dict mapping a property key to a list of gene names. Valid keys are 'fill', 'stroke', 'outline', 'color', 'bold', 'italic', 'underline', 'halo'. A gene may appear under multiple keys; all applicable properties are applied independently.

highlight_color : str = None

Deprecated alias for highlight_fill_color. Retained for backward compatibility with the list form of highlight.

highlight_fill_color : str = None

Exon fill colour for 'fill' highlights.

highlight_spine_color : str = None

Backbone colour for 'stroke' highlights.

highlight_outline_color : str = None

Exon outline colour for 'outline' highlights.

highlight_label_color : str = None

Gene-name text colour for 'color' highlights.

highlight_halo_color : str = None

Halo rectangle colour (may include alpha) for 'halo' highlights.

tip_fmt : str = None

Python format string for tooltips. Available keys: {name}, {strand}, {start}, {end}.

tip_label : str = None

Heading shown above the tooltip body. Defaults to f'{name}:'.

Returns

: Tracks

self, to support fluent chaining.

Raises

: ValueError

If neither or both of genes_data and assembly are given, or if highlight carries an unknown property key.

add_heatmap_track

geneinfo.widget.Tracks.add_heatmap_track(
    df,
    name,
    *,
    start='start',
    end='end',
    individual_col=None,
    group_by=None,
    sort_by=None,
    color_map=None,
    value_col=None,
    palette=None,
    vmin=None,
    vmax=None,
    height=None,
    zoom_windows=1000,
    alpha=0.5,
    shade=None,
    tip_fmt=None,
    tip_label=None,
    group_col=None,
    windows=None,
    density_windows=None,
)

Add a heatmap track — one row per individual, GPU texture rendering.

Parameters

df : pandas.DataFrame

Long-format frame with columns chrom, the interval start and end columns (see start / end), and the columns named by individual_col / group_by when given.

name : str

Track display label shown in the left panel.

start : str = \'start\', \'end\'

Columns holding each interval’s start and end coordinates.

end : str = \'start\', \'end\'

Columns holding each interval’s start and end coordinates.

individual_col : str = None

Column identifying each haplotype / sample row. When omitted, each group (or the whole table, without group_by) is drawn as a single row, e.g. for an annotation track, and shade defaults to 'count'.

group_by : str = None

Column for grouping individuals into coloured bands.

sort_by : str = None

Column used to sort individuals within each group.

color_map : dict = None

{group_value: '#rrggbb'}. When omitted, colours cycle through the built-in palette in group order. Only used in density mode (when value_col is None).

value_col : str = None

Column whose per-segment values drive colouring. When omitted, the track renders in density mode (overlapping segments accumulate alpha, tinted per group).

palette : str, list, dict, or matplotlib.colors.Colormap = None

Palette used when value_col is given. A colormap name ('viridis') or Colormap instance triggers continuous mode; a {category: colour} dict or list of colours triggers discrete mode (up to 255 categories). Ignored when value_col is None. When value_col is given but palette is omitted, a default is auto-picked: 'viridis' for numeric columns, the built-in categorical cycle otherwise.

vmin : float = None

Continuous-mode normalisation range; auto-inferred from df[value_col] when omitted. Ignored in discrete mode.

vmax : float = None

Continuous-mode normalisation range; auto-inferred from df[value_col] when omitted. Ignored in discrete mode.

height : int = None

Track height in CSS pixels. Defaults to max(90, n_individuals), i.e. at least one pixel per row.

zoom_windows : int, str, or tuple thereof = 1000

Finest x-resolution of the binning. An int is a fixed bin count covering the binned span. A str is a physical bin size in base pairs ('10kb', '1.5Mb', '500' — units bp/kb/Mb/Gb, bare number means bp); the bin count is then derived from the span as ceil(span / size). Because the heatmap rebins to the visible window (the ⟲ button), a bp size yields a constant bp-per-bin resolution that reaches its full fineness once you zoom in — at whole-chromosome zoom it is capped at 8192 bins (a GPU texture-width limit). A tuple is accepted for symmetry with the other track types; the heatmap renders a single resolution, so it uses the finest entry for the current span.

alpha : float = 0.5

Per-segment opacity (matplotlib-style). Density mode with shade='alpha' only — each overlapping segment adds alpha to the cell shading, clamped at 1.0. Must lie in (0, 1].

shade : ('alpha', 'count', 'log_count') = 'alpha'

How density mode (no value_col) shades a cell. Defaults to 'alpha' with individual_col and to 'count' without it, where many records share each row. 'alpha' adds alpha per overlapping segment, which suits one row per sample, where a few segments overlap a cell. 'count' shades by the number of segments overlapping the cell, scaled so the busiest cell in the binned window (the chromosome, or the view after ⟲) is fully shaded; use it when many records share a row, e.g. a whole annotation track. 'log_count' scales log(1 + count) instead, keeping sparse regions visible next to hotspots. In the count modes the tooltip reports the cell’s segment count.

tip_fmt : str = None

Python format string for tooltips. Available keys: {group}, {individual}, {nInd}.

tip_label : str = None

Heading shown above the tooltip body. Defaults to f'{name}:'.

group_col : str | None = None

Deprecated aliases of group_by (group_col) and zoom_windows (windows, density_windows). Passing one emits a DeprecationWarning.

windows : str | None = None

Deprecated aliases of group_by (group_col) and zoom_windows (windows, density_windows). Passing one emits a DeprecationWarning.

density_windows : str | None = None

Deprecated aliases of group_by (group_col) and zoom_windows (windows, density_windows). Passing one emits a DeprecationWarning.

Returns

: Tracks

self, to support fluent chaining.

Raises

: ValueError

If alpha is not in (0, 1], if shade is unknown or not 'alpha' together with value_col, if palette is supplied without value_col, if value_col is missing from df, or if a discrete palette has more than 255 categories.

Add a histogram track — vertical bars centred on each x.

Parameters

df : pandas.DataFrame

Long-format frame with columns chrom, the column named by x, and the column named by y.

Track display label shown in the left panel.

x : str = \'pos\'

Column for genomic position (the bin centre).

y : str = \'value\'

Column for bar height.

group_by : str = None

Column whose unique values become separate groups.

color_map : dict = None

select_tracks

geneinfo.widget.Tracks.select_tracks(*names)

Show only the listed tracks, in the order listed.

A shortcut for hiding every track, then showing the listed ones, except that the shown tracks are also reordered to follow names. The remaining tracks stay hidden, after the shown ones and in their existing order, so their data is kept and a later :meth:show_track or :meth:select_tracks restores them instantly.

Parameters

*names : str, int, or iterable of str or int = ()

Tracks to show, as separate arguments (select_tracks('a', 'b')), as one list (select_tracks(['a', 'b'])), or a mix. Each entry is a display name, which selects every track with that name (in their existing order), or a positional index into :attr:track_configs as it is before the call. A track listed twice is placed at its first mention. No entries (an empty call or an empty list) hides every track.

zoom_to

geneinfo.widget.Tracks.zoom_to(
    chrom,
    start=None,
    end=None,
    *,
    center=None,
    window=None,
)

Zoom the viewport to a chromosome, range, or centred window.

Supports three calling styles:

  • zoom_to('chrX') — show the whole chromosome.
  • zoom_to('chrX', start=100_000, end=200_000) — show the given half-open range [start, end). start and end may also be passed positionally.
  • zoom_to('chrX', center=150_000, window=1_000_000) — centre on center with the given window width. window defaults to 1_000_000 bp when omitted.

The start/end and center/window styles are mutually exclusive.

Parameters

chrom : str

Chromosome name.

start : int = None

Inclusive start position in base pairs. When given, end must also be given (and center/window must not).

end : int = None

Exclusive end position in base pairs.

center : int = None

Genomic position to centre on, in base pairs. Keyword-only.

window : int = None

Total window width in base pairs. Keyword-only. Defaults to 1_000_000 when center is given. The viewport is set to [center - window // 2, center + window // 2) then clamped to the chromosome bounds by :meth:set_viewport.

Returns

: Tracks

self, to support fluent chaining.
